# Unit ledger — MAP-STRUCT-KEY-SUBSCRIPT-1 · a map subscript with a struct key is planned through RePark's own `element_at` kernel, never DataFusion's `get_field` (AUD-016)

**Date:** 2026-11-01 (the unit's work; the records are dated 2026-11-02) · **Branch:** `fix/map-struct-key-subscript-1` (local; not pushed; not merged) · **Base:** `aa52bd5f` (`main` after the RP-64 post-merge records, #1229) · **Model:** builder `claude-opus-5-5` (commits `237c7ae0` and `4f0bef97`; the id verified from the task transcript); clerk `claude-haiku-5-5` (the records commit on this branch) · **Policy:** [../../../AGENTS.md](../../../AGENTS.md).
**Path:** STANDARD. **risk_tier: standard.**

**Why now.** Third audit finding AUD-016 (High): `m[named_struct(...)]` on a map whose key type is a struct panics inside DataFusion 54.1.0's `get_field` (the sliced `BooleanBuffer` assertion, reported as `repark internal error` on an ordinary SELECT), where Spark 4.1.2 answers the value. `element_at` on the same map was already correct. Reproduced by the orchestrator on 2026-11-01 with a two-field key over a two-entry map. The card is MAP-STRUCT-KEY-SUBSCRIPT-1 (filed 2026-11-01, grade A, P1); its Status closure and the label ledger's clause C-080 are not on this branch (see Records).

**The fix.** A new analyzer rule `SparkMapSubscript` (`crates/repark-functions/src/collection/map_subscript.rs`), installed right after `SparkMapRewrite` on the Spark door (`registration.rs`), the ANSI door (`repark-sql` `dialect.rs`) and the native door (`repark-python` `session_runtime.rs`). It runs after the last type coercion. It rewrites `get_field(map, key)` when the map's key type is nested (struct, array or map) into `element_at(map, CAST(key AS <map key type>))`, which is RePark's own `element_at` kernel. Spark casts the lookup key by position, so a renamed struct key is rebuilt positionally first, recursively at every struct level. A struct key whose field count differs at any level refuses at plan time with `DATATYPE_MISMATCH.UNEXPECTED_INPUT_TYPE`, naming the required key type. Scalar-key subscripts keep DataFusion's path unchanged.

**Not in this unit.** The residue listed in the Records section and carded below (R1 is a kept wording divergence, recorded in C-015 with no card). The `element_at` shape divergence (R2, card ELEMENT-AT-STRUCT-KEY-SHAPE-1), the per-row scalar key (R3, card MAP-SUBSCRIPT-PER-ROW-SCALAR-KEY-1) and the hadoop-type facade fresh-session gap (R4, card HADOOP-FACADE-FRESH-SESSION-1). The native door `repark.sql()` is wired but not pinned here (C-019). The fresh-session hadoop divergence (R4) is a recorded design divergence, not a residue to fix.
