**Path:** STANDARD. **risk_tier: standard.**

**Why now.** Third audit finding AUD-016 (High): `m[named_struct(...)]` on a map whose key type is a struct panics inside DataFusion 54.1.0's `get_field` (the sliced `BooleanBuffer` assertion, reported as `repark internal error` on an ordinary SELECT), where Spark 4.1.2 answers the value. `element_at` on the same map was already correct. Reproduced by the orchestrator on 2026-11-01 with a two-field key over a two-entry map. The card is MAP-STRUCT-KEY-SUBSCRIPT-1 (filed 2026-11-01, grade A, P1); its Status closure and the label ledger's clause C-080 are not on this branch (see Records).

**The fix.** A new analyzer rule `SparkMapSubscript` (`crates/repark-functions/src/collection/map_subscript.rs`), seated just before `type_coercion` (fix round 1) on the Spark door (`repark-spark` `extension.rs`), the ANSI door (`repark-sql` `dialect.rs`), the Python native door (`repark-python` `session_runtime.rs`) and the DataFrame expression context (`repark-python` `column/expr_build.rs`); the post-coercion entry in `analyzer_rules()` stays for the contexts that only append that list. It rewrites a subscript (`get_field`, `array_element` or `__repark_get_item__`) whose first argument is a map with a nested key type (struct, array or map) into `element_at(map, <key rebuilt by position>)`, RePark's own `element_at` kernel. The key is rebuilt by position at every depth by `__repark_key_by_position__` (`crates/repark-functions/src/collection/key_by_position.rs`, fix round 1): struct fields, list elements and map entries, with Arrow's cast used only on leaves. A leaf of a kind Spark does not accept, and a struct key of another field count, refuse at plan time with `DATATYPE_MISMATCH.UNEXPECTED_INPUT_TYPE`, naming both types in Spark notation. Scalar-key subscripts keep DataFusion's path unchanged. *Correction 2026-11-02, after the round-1 verifier (F1):* the round-0 text said the key was rebuilt by position at every struct level and cast by position for nested keys; the positional cast held at every depth only from fix round 1, because the round-0 code cast a struct inside an array key by name. *Correction 2026-11-02, after the round-2 verifier (F7):* "positional at every depth" holds only with the leaves cast by the Spark door's own cast (C-033, C-035, C-036); the kernel `__repark_key_by_position__` is structural only from fix round 2 (leaves keep their source type, and the leaf cast is applied in `map_subscript.rs` at the expression level); the list family (List, LargeList, FixedSizeList) is one kind at every depth (C-034, C-037). *Correction 2026-11-02, after the round-3 verifier (F1, F3, F4):* the leaf cast is the Spark door's CAST at every depth, with the session zone (`LeafCaster` in `key_by_position.rs`, fix round 3; C-042, C-043); the round-2 reuse of two rewrites by hand was not that cast (F3); floating leaves are normalised on both sides of the lookup, inside the subscript pipeline only (C-041).
