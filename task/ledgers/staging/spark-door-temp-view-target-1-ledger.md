# Unit ledger — SPARK-DOOR-TEMP-VIEW-TARGET-1 · a temporary view's name never resolves to the same-named table on a write

**Date:** 2026-10-29 · **Branch:** `fix/spark-door-temp-view-target-1` (not pushed when this ledger was written) · **Base:** `c48b1ad7` (`main`, the branch point) · **Product head:** `3243444a` (fix round 1 on the product fix `7984ed39`, whose test commit is `fe4879d3`; the merge of main is `ce4a25ef`) · **Model:** builder `claude-opus-5-5` (the two product commits and the fix round's four commits); clerk `claude-haiku-5-5` (the records commits) · **Policy:** [../../../AGENTS.md](../../../AGENTS.md).
**Path:** STANDARD.

**Retires:** this ledger moves to `../completed/` on the merge. The re-verification after fix round 1 and the merge are OPEN clauses below; the ledger does not close before them.

**Why now.** AUD-006 of the second independent audit (2026-10-29, [the report](../../../docs/audits/iceberg-v2-label-independent-reaudit-2026-10-29.md), section 3; minimal reproduction in its section 9) is Critical. With a temporary view in scope under a one-part name that is also the name of an Iceberg table in the current namespace, the Spark door sent `DELETE`, `UPDATE`, `MERGE INTO`, `INSERT`, `INSERT OVERWRITE` and `TRUNCATE TABLE` to the table, while `SELECT` in the same session read the view. Spark 4.1.2 refuses every one of those writes, so RePark changed a table by statements Spark refuses, and the change was silent. The base `c48b1ad7` gives the same results, so the fault predates the shared DML target resolver. Card: [SPARK-DOOR-TEMP-VIEW-TARGET-1](../../roadmap/mid-term/spark-door-temp-view-target-1-card-2026-10-29.md).

**Where the fault lived.** The Python facade, not the Rust resolver. Its write-target expansions in `session_core.py` (`_try_expand_insert_sql` for INSERT INTO and INSERT OVERWRITE, `_try_expand_update_sql`, `_try_expand_delete_sql`, and the target of `_expand_merge_into_sql`) and in `sql_relations.py` (`_expand_truncate_target_sql`) resolved a one-part target with `prefer_temp_view=False`, so `t` became the current catalog and namespace's `t` before the native door saw the statement. Reads used `prefer_temp_view=True` and went to the view. The card's site line (`crates/repark-spark/src/dml_target.rs`, `resolve_dml_target`, `qualify_table_parts`) is corrected in the card's dated paragraph. On the Rust door alone a bare write already fell on the view, with DataFusion's own error text. The single source of truth for "is this name a temporary view" is `ReparkSession::resolve_temp_view_home_ref`, which the Spark door and the facade (`_native.resolve_temp_view_home_ref_for_session`) both reach, so the fix adds no second registry.

**The change.** One commit of product code and one of tests; the head is `7984ed39`.
1. **Facade (five one-token edits).** The five expansions above now resolve their target with `prefer_temp_view=True`, the read side's lookup. A view-named target becomes the view's home-qualified name, and every other name is qualified as before. CREATE TABLE, durable CREATE VIEW and the DataFrame writer paths are unchanged.
2. **Spark door (one shared check).** `crates/repark-spark/src/view_ddl/temp_write.rs` (new) defines `refuse_temp_view_write_target`. `view_ddl::temp_ddl::route_temp_view_statement` calls it for every `session.sql` statement that reaches the temporary-view router, ahead of the write routes, so the check runs before any write route qualifies, loads, stages, branches or writes. It parses only the target of `DELETE FROM`, `UPDATE`, `MERGE INTO`, `INSERT [INTO | OVERWRITE] [TABLE]` (not `[LOCAL] DIRECTORY`) and `TRUNCATE TABLE`. It resolves the target through `temp_view_home_segments`, which is now `pub(crate)` and shared with DROP and DESCRIBE. A hit refuses with a `DataFusionError::Plan` carrying the Spark-shaped text in the table below. A resolution error counts as "not a view", so an ordinary write never fails because of the check.
3. **Write-options precedence.** The check runs only when the statement's write-options map is empty (ruling 3 below).

**Spark 4.1.2 answers the unit matches** (builder's step-0 probe on the audit's sequence, table `1,2,3`, temporary view `t` over `SELECT 99 AS id`, current namespace the table's; identical on copy-on-write and merge-on-read; copied from the builder's hand-back, not re-measured):

| Route (one-part name `t`) | Spark 4.1.2 | RePark at `7984ed39` |
|---|---|---|
| `DELETE FROM t WHERE id = 2` | `org.apache.spark.SparkException [INTERNAL_ERROR]` on a view over a literal (the orchestrator's measurement, ruling 4; the builder's probe captured only the Py4J wrapper) | `EXPECT_TABLE_NOT_VIEW.NO_ALTERNATIVE`, the table unchanged |
| `UPDATE t SET …` | `UNSUPPORTED_FEATURE.TABLE_OPERATION` (does not support UPDATE TABLE) | the same class, names the view, the table unchanged |

Backticks and upper case (`T`) behave as the bare name. `global_temp.t` refuses on Spark with the same classes, but RePark already refuses `CREATE GLOBAL TEMPORARY VIEW`, so no two-part check exists.

**Unchanged.** The existing pin `python/repark/tests/writes/test_ice_write_options_1.py::test_non_iceberg_overwrite_refuses_write_options` (no edit). No existing test file was edited: the diff stat of `c48b1ad7..7984ed39` shows two new test files and product edits only. **Rulings (dated 2026-10-29).**
1. **Scope.** The orchestrator accepted the five facade edits plus the shared Rust check as inside the unit, because the facade is where the view is lost and the Rust check is the only single source of the refusal on both doors.
2. **Refusal text.** The refusal texts echo the statement's own operation token, as Spark and `truncate.rs` do (ruling 76(a)). No hint names an action, so no hint names a data-deleting action. Through the facade, `TRUNCATE TABLE T` names `` `t` `` where Spark names `` `T` ``. The class and the shape match; the difference is the folded name the facade has already resolved.
3. **Write-options precedence.** When a statement carries write options, the existing write-options refusal comes first. This follows the router's order for DROP and DESCRIBE (`refuse_if_non_empty` ahead of the temporary-view action). The first build ran the check ahead of everything, which made the existing pin `test_non_iceberg_overwrite_refuses_write_options` red, so the check now runs only when the write-options map is empty. The table stays unchanged on both paths; the Rust control `a_view_name_with_write_options_still_holds_the_table` pins that. The existing pin is unchanged.
4. **DELETE class.** The orchestrator measured on 2026-10-29 that Spark 4.1.2 fails `DELETE FROM t WHERE id = 2` and `DELETE FROM t` on a temporary view over a literal with `org.apache.spark.SparkException [INTERNAL_ERROR] Unexpected table relation: Project [99 AS id]`, with the table unchanged. The builder's step-0 probe captured only the Py4J wrapper of the same statement, not the Java class. RePark therefore refuses DELETE with `EXPECT_TABLE_NOT_VIEW.NO_ALTERNATIVE`, a Spark-shaped class in place of Spark's internal error. This is a choice of class, not a parity claim; the table outcome matches Spark.
5. **Leads are carded, not built.** The DELETE through a view over a table (Spark executes it, matching rows and non-matching rows, on both table kinds; RePark refused it with `TableNotFound` before this unit and refuses it with the view class now, so the refusal is not widened) is carded as SPARK-DOOR-DELETE-THROUGH-VIEW-1. The DataFrame writer paths and the Rust-door `USE` gap are carded as WRITER-PATH-TEMP-VIEW-TARGET-1.

### Design

- **One rule, read in one place (core).** `SqlDialect` gains a defaulted `temp_view_name_rule` (default `None`, so the ANSI and DataFusion doors are unchanged). `SparkDialect` answers it from `spark.sql.caseSensitive`. `ReparkSession` applies it in `temp_view_ref` and `temp_view_ref_from_segment`, which are the choke points for every lookup, and `TempViewSession` gains a defaulted `temp_view_target_ref` for the reference a CREATE registers under. There is no second registry.
- **Default (`IgnoreCase`).** A view keeps its created spelling. A lookup that misses exactly falls back to the unique case-insensitive twin, so a write, read, drop or replace through any spelling reaches the one view. Rejected alternative: lower-casing every name at registration, which would make `` SELECT * FROM `V` `` miss a view created as `` `V` `` on the Rust door and would redden the existing stub test `temp_view_quoted_name_reaches_the_session_quoted`.
- **`caseSensitive=true` (`Exact`).** Registration and lookup are verbatim, unquoted names included, as in Spark. This closes the S2: a write through `t` reaches the table while `T` refuses.
- **F-2.** `DataFrameWriterV2._existing_table_ref` (shared by `append`, `overwritePartitions` and `overwrite`, and their option forms) first calls `writer_layout._refuse_temp_view_write_target`. A hit raises `AnalysisException` with `_LEGACY_ERROR_TEMP_1011` before anything is resolved, staged or written. `create`, `createOrReplace`, `replace`, `insertInto` and `saveAsTable` are unchanged, as Spark measures. The helper lives in `writer_layout.py` because `writer_readwriter.py` is at its size ceiling.
- **MERGE WITH SCHEMA EVOLUTION.** The Spark door's view check accepts the spelling (`merge_head`), so a view name refuses with the MERGE class. The facade does not expand the spelling; that is C-017.
