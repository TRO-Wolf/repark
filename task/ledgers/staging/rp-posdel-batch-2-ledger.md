# Unit ledger — RP-POSDEL-BATCH-2 · RePark's own position-delete writers write bounded batches

**Date:** 2026-10-28 · **Branch:** `fix/rp-posdel-batch-2` · **Base:** `321c6095` (`main`, the branch point) · **Model:** builder `claude-opus-5-5` (commits `fc3afd8a`, `c0336a62`, `105e49bb` and the stress-pin commit); clerk `claude-haiku-5-5` (the records commits) · **Policy:** [../../../AGENTS.md](../../../AGENTS.md).
**PR:** #1203, open; not merged. **Path:** STANDARD. **risk_tier: standard.**

**Retires:** this ledger moves to `../completed/` when the unit's last commit lands.

**Why now.** RP-60 (PR #1200) repinned the fork to its batched position-delete writer, so the bulk `BETWEEN` `DELETE` completes. RePark's own position-delete writers did not change: each still builds one `Utf8` array over a whole partition, or over a whole identity set, so a merge-on-read `MERGE`, an identity-IN `DELETE` or `UPDATE`, the copy-on-write identity scratch table and a plain `DELETE` spelled `>= AND <` still panic with `offset overflow` past about 2 GiB of path text in one partition. Card: [the RP-POSDEL-BATCH-2 card](../../roadmap/mid-term/rp-posdel-batch-2-card-2026-10-27.md).

**Scope.** Product: `crates/repark-iceberg/src/write/position_delete_batch.rs` (new), one `mod` line in `write/mod.rs`, `write/position_delete.rs` (site 1), `write/predicate_dml.rs` (site 2) and `write/predicate_dml/cow_commit.rs` (both copy-on-write identity callers). Tests: `crates/repark-spark/tests/posdel_batch_door.rs`. Records: the map rows, the registry row, the release notes, the card and this ledger. No `Cargo.toml` or `Cargo.lock` line changes; the fork pin stays at `ea0b7741`.
