# Unit ledger — SPARK-DOOR-TEMP-VIEW-DDL-1 · an `ALTER TABLE` through a temporary view's name refuses as Spark 4.1.2 does, and `RENAME TO` renames the view

**Date:** 2026-11-02 (the unit's work was done 2026-11-01) · **Branch:** `fix/spark-door-temp-view-ddl-1` (not pushed when this ledger was written) · **Base:** `aa52bd5f` (`main`, the branch point) · **Head:** `c45fc2b2` (the pins `9b2c5de5` and `efbe174b`, red at base; the fixes `4f090c3f` and `97efa4ba`; the records `d83f7613` and `0d3f01ab`; the fix round 2 pins `778bfc84` and fix `fd0ae8f1`; the fix round 2 records `90c2cc0d`; the fix round 3 pins `bfd8b54f`, fix `89841853` and the body-hash baseline `c45fc2b2`) · **Model:** builder `claude-opus-5-5` (the four product commits); clerk `claude-haiku-5-5` (the records commits) · **Policy:** [../../../AGENTS.md](../../../AGENTS.md).
**Path:** STANDARD.

**Why now.** AUD-015 of the third independent audit (2026-11-01, Critical) is an `ALTER TABLE` fault on the Spark door. With a temporary view `t` in scope under the name of an Iceberg table in the current namespace, every `ALTER TABLE t ...` form reached the same-named table: `DROP COLUMN` and `REPLACE COLUMNS` removed values from every current read, and `RENAME TO` renamed the table on the memory catalog. Spark 4.1.2 refuses each of these with `EXPECT_TABLE_NOT_VIEW` and leaves the table unchanged; for `RENAME TO` it renames the view. The fault predates the audit: the base `aa52bd5f` gives the same results on the memory catalog (`mem`) and the hadoop catalog (`hd`). [SPARK-DOOR-TEMP-VIEW-TARGET-1](../completed/spark-door-temp-view-target-1-ledger.md) (AUD-006) covered the six write heads only, so this is the same family on the DDL side. The orchestrator reproduced the fault on 2026-11-01, and the builder reproduced it at `aa52bd5f` on both catalogs (twelve or more forms changed the table). The audit's card and label clause sit on PR #1230 (`docs/audit3-records`), which is not on this branch.

**The change.** Two product commits and one new module.

1. `crates/repark-spark/src/view_ddl/temp_alter.rs` (new): parses the target of `ALTER TABLE [IF EXISTS] <name>` and the head of the operation, builds Spark's refusal texts, and renames the view for `RENAME TO`. The target resolves through `temp_view_home_segments`, which the AUD-006 check, DROP and DESCRIBE already share, so the case rule is the AUD-006 rule. A resolution error counts as "not a view", so an ordinary ALTER never fails because of the check. Correction 2026-11-02 (verifier round 3, F10; fix round 3): that sentence is superseded. A lookup error now refuses every head that consults it, and the view registry decides on the raw token of a name the segment parser rejects (see Fix round 3). Correction 2026-11-02 (verifier round 1, F1): the target is read with sqlparser's own grammar, `ALTER [ICEBERG] TABLE [IF EXISTS] [ONLY] <name> [ON CLUSTER <ident>]`, and an unknown head fails closed; see Fix round 1.
2. `temp_ddl.rs`: `route_temp_view_statement` calls `route_temp_view_alter` after the AUD-006 write check, when the write-options map is empty and the head word is `ALTER`, so the check runs before every ALTER route. Correction 2026-11-02 (verifier round 2, F5): a leading `;` now refuses before any route, and the statement's first token is read after whitespace and comments; see Fix round 2.
3. `temp_view.rs`: `renamed_temp_view` rebuilds a SQL temp view under its new name and home. `temp_write.rs`: `quoted` and `written_leaf` become `pub(crate)` for `temp_alter.rs`.

Spark 4.1.2's operation words, and the class each takes:

| Head | Class |
|---|---|
| ADD COLUMN(S), ADD and DROP and RENAME of a bare column (RePark-only spellings), ADD and DROP PARTITION, ADD and DROP CONSTRAINT, DROP COLUMN(S), RENAME COLUMN, ALTER COLUMN, CHANGE COLUMN, REPLACE COLUMNS, SET LOCATION, RENAME TO PARTITION, CLUSTER BY, RECOVER PARTITIONS | `EXPECT_TABLE_NOT_VIEW.NO_ALTERNATIVE` |
| SET TBLPROPERTIES, UNSET TBLPROPERTIES, SET SERDE, SET SERDEPROPERTIES | `EXPECT_TABLE_NOT_VIEW.USE_ALTER_VIEW` |
| RENAME TO `<name>` | renames the view |
| ADD, DROP and REPLACE PARTITION FIELD, WRITE ..., SET and DROP IDENTIFIER FIELDS, CREATE, REPLACE and DROP BRANCH or TAG | pass through to the table, as on Spark |

The texts are Spark's, copied byte for byte, including the double space before `SQLSTATE` that Spark prints in the NO_ALTERNATIVE class. Example: ``[EXPECT_TABLE_NOT_VIEW.NO_ALTERNATIVE] 'ALTER TABLE ... DROP COLUMNS' expects a table but `t` is a view.  SQLSTATE: 42809``. The shown name is the written leaf: `ALTER TABLE T` over view `t` shows `` `T` ``. RePark prefixes `Error during planning: ` as it does for every plan error.

**Spark 4.1.2 answers.** The builder measured them in four probe rounds on Spark 4.1.2 with Iceberg 1.11.0 (catalog `hd`, one JVM at a time), with a view `t` over `SELECT 99 AS id` in the table's namespace. The answers are copied from the builder's hand-back; the clerk did not re-measure them. The facts the clauses rest on: `ALTER TABLE t RENAME TO t2` answers ok and then `t` reads the table; a RENAME TO onto an existing view name refuses `TABLE_OR_VIEW_ALREADY_EXISTS`; the Iceberg extension forms answer ok on the table; a three-part RENAME TO destination refuses `IDENTIFIER_TOO_MANY_NAME_PARTS`; the RePark-only spellings answer `PARSE_SYNTAX_ERROR`.
