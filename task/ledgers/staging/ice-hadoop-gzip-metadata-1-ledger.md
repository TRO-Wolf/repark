# Unit ledger — ICE-HADOOP-GZIP-METADATA-1 · the hadoop path read follows Java's gzip metadata names for the hinted version, the hint walk and the no-hint listing

**Why now.** ICE-HADOOP-HINT-WINDOW-1 (PR #1205) made the path read of a `type=hadoop` table walk past `version-hint.text` through the plain names only. Java's writer also names metadata files `v<N>.gz.metadata.json`, when `write.metadata.compression-codec` is gzip, and `v<N>.metadata.json.gz`. The hinted lookup, the walk and the no-hint listing did not see them. A stale hint then still returned a deleted row: the second independent audit (AUD-007, Critical) measured ids 1, 2, 3 where Spark answers 2, 3 on the same files. The same gap also refuses where Spark answers (AUD-010, Medium): a gzip-named current file makes the read refuse with a message that names a plain file which does not exist. The card is [ICE-HADOOP-GZIP-METADATA-1](../../roadmap/mid-term/ice-hadoop-gzip-metadata-1-card-2026-10-29.md); the findings are in [the second audit](../../../docs/audits/iceberg-v2-label-independent-reaudit-2026-10-29.md), section 3.

**The change.** `crates/repark-core/src/iceberg_path.rs`. `hadoop_metadata_file` probes `v<N>.metadata.json`, `v<N>.gz.metadata.json` and `v<N>.metadata.json.gz` in that order, Java's order (`TableMetadataParser.Codec` is declared `NONE, GZIP`, and the legacy suffix comes last), and returns the first name that exists. Three callers use it: the hinted version (`resolve_metadata_location`), every step of the walk (`newest_from_hint`) and, through `metadata_file_order`, the no-hint listing (`latest_metadata_location`). The listing ranks a version's names as plain 3, gz infix 2, legacy 1, so one version under two names resolves to the plain name. A `NNNNN-<uuid>.metadata.json` name keeps rank 3, so its tie with a plain `v` name keeps main's last-listed-wins behaviour. The walk bound (10,000) and the Java `int` stop are unchanged. The walk-limit refusal names the hinted file actually found, so on a gzip table it names `v<N>.gz.metadata.json`; on a plain table the text is byte-identical. `metadata_file_version` is now a `#[cfg(test)]` wrapper over `metadata_file_order`.

**Unchanged.** The missing-hinted-file error, which still names the plain `v<N>.metadata.json`; the unparsable, non-UTF-8, negative, `u64`-overflowing and out-of-range hint, which still falls back to the listing (the listing now sees the compressed names); the no-hint listing rules for plain and uuid names; the walk bound and the Java `int` stop; an explicit `*.metadata.json` path, read verbatim; the texts of plain tables. No existing test changed. Dated correction 2026-10-29 (verifier S3-4): for a negative hint RePark falls back to the listing where Java refuses. Java's `parseInt` reads `-1` and the read refuses, so the registry's sentence that places a negative hint "like" `HadoopTableOperations.findVersion` does not hold for that value; this paragraph's statement is true of RePark. Carded as [HADOOP-HINT-NEGATIVE-1](../../roadmap/mid-term/hadoop-hint-negative-1-card-2026-10-29.md) (grade C, open, awaiting charter): a leniency, not a wrong value, and this unit leaves it unchanged.

**The deviation (dated 2026-10-29, accepted by the orchestrator).** The card's Fix paragraph records a charter ruling: a hint that names a version with no file under any name falls back to the listing, as Spark does. This unit reverses that ruling. The ground for it was the audit's cleanup shape, `spark_cleanup_stale_hint_to_deleted_v2`, where Spark answered `[1..5]`, and that answer was a probe artefact. The probe rewrote `version-hint.text` and left Hadoop's `.version-hint.text.crc` sidecar stale. Spark logged a `ChecksumException` reading the hint at the stale-hint reads (12:16:12 and 12:16:13 in the audit's probe log), treated the hint as unreadable and fell back to its listing. With a readable hint, Iceberg 1.11.0 Java refuses a version with no file under any name (`Metadata file for version %d is missing under %s`), as the audit's `rp_table_hint_past_newest` and `rp_table_hint_zero` cases show. So a readable hint that names a version absent under all three names still refuses with its existing text. The three existing pins of that text are untouched. AUD-010 narrows to its first shape, a gzip-named current file, which is fixed.
