- R-DEL-4 (round 2, Q4): MERGE gets an up-front check before any file is written, on an explicit or inherited Avro or ORC delete format.

## Design reasoning

The delete format is resolved in one place, `resolve_delete_format`. It returns Puffin on format version 3 before any setting. Otherwise it returns the explicit per-write option or table property if one is set, and Parquet if not. It no longer falls back to the data format, so an inherited Avro or ORC format writes Parquet on RePark's own writers. An explicit Avro or ORC refuses with a Plan error, before the position-delete file is written, and the hint names `write.delete.format.default` and `parquet`.

On the Spark door, the fork route cannot be changed, so the guard refuses before passthrough when the statement would reach the fork writer on an inherited Avro or ORC table, and refuses every route on an explicit one. The fork-bound test mirrors the claim chain in the identity-DML router: the IN-list and BETWEEN DELETE claims, the UPDATE claim, then the plain identity claim, with `plain_identity_needs_fork` as the last test. MERGE is RePark-owned and gets an up-front check next to the encryption check, before fragment rewrite and before execution.
