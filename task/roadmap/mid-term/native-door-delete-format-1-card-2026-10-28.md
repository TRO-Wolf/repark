# Card NATIVE-DOOR-DELETE-FORMAT-1: the native door's DELETE, UPDATE and inherited-format MERGE are measured on the repinned fork; the committed pin is owed

**Date:** 2026-10-28. **Filed by:** the ICE-DELETE-FORMAT-GUARD-1 clerk round (`claude-haiku-5-5`), from the coordinator's ruling Q1 on the builder's round-2 hand-back (the native door's exposure is a follow-up, not part of AUD-003). **Narrowed by:** the RP-61 clerk round (`claude-haiku-5-5`), on the Opus 5.5 verifier's and the Muse MAX critic's measurements at `67dcaed5`.

**Status:** open, for the committed native-door pin only. Grade C (clerk). Not dispatched. The shapes below are measured on the repinned fork (see Measured), and no committed pin covers them yet (RP-61 ledger C-017, OPEN). No build is owed until the owner charters the pin.

**Why:** ICE-DELETE-FORMAT-GUARD-1 (ledger [ice-delete-format-guard-1](../../ledgers/staging/ice-delete-format-guard-1-ledger.md), AUD-003) guarded the Spark door: its router (`crates/repark-spark/src/router/delete_update.rs`) and its MERGE router (`crates/repark-spark/src/merge.rs`). The native door (`repark.sql()`, `crates/repark-sql`) had no such guard. Before the RP-61 repin, a native DELETE or UPDATE that reached the fork writer on a format-version 2 merge-on-read table whose delete format was explicit Avro or ORC, or inherited from `write.format.default` Avro or ORC, could write a delete file that the fork could not read, after the statement reported success. RP-61 repins the fork to `56aa8913`, which reads Avro and ORC delete files, and reverts the interim Parquet default, so the RePark route writes the data format again. The shapes were then measured on the repinned fork (Measured below).

Native MERGE had no up-front check on the native door. Before RP-61 its RePark writer refused an explicit Avro or ORC format only at the position-delete write, so the data files the statement wrote earlier were not committed, and whether every such file was removed was not measured. On the repinned fork, native MERGE on inherited Avro and ORC matches the Parquet outcome (Measured below).

**Measured:**
- Before the RP-61 repin (fork `ea0b7741`), on the native door, by the Muse MAX critic in the ICE-DELETE-FORMAT-GUARD-1 verifier round: a native `BETWEEN` DELETE on an inherited Avro table leaves the table unreadable; a native scalar DELETE writes a readable Parquet delete; a native `BETWEEN` DELETE on an explicit Avro delete format leaves the table unreadable. The builder did not run the native door, and the Spark-door red runs do not cover it.
- On the RP-61 pin (fork `56aa8913`, RP-61 at `67dcaed5`), by the Opus 5.5 verifier, copied and not re-run by the clerk: the native door's fork-route BETWEEN DELETE, scalar DELETE and BETWEEN UPDATE on an inherited Avro table, an inherited ORC table and an explicit Avro delete format write their delete files in the data format and read back. The same shapes were unreadable on the old pin.
- On the same head, by the Muse MAX critic (`muse-spark-1.3`, effort max), copied and not re-run by the clerk: the native door's DELETE, UPDATE and MERGE probes pass, and native MERGE on inherited Avro and ORC matches the Parquet outcome on this pin.

**Fix:** none is proposed for these shapes, because they are measured on the repinned fork. The remaining item is a committed native-door pin for the shapes above (red on `ea0b7741`, green on `56aa8913`), which the owner charters. A pin that finds any of these shapes unreadable on the head reopens this card as a fix; `crates/repark-spark/tests/delete_format_guard.rs` is the model for its pins.

**Retires:** the card when the native-door pin merges, or when a red run on the head reopens it as a fix and a later green run closes that fix.
