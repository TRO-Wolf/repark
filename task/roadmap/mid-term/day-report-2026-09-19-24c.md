## 3. What the measurements showed

- **The scalar string→TIMESTAMP cast was silently wrong.** Closing IPI-02 routed time-travel strings through the engine's CAST, which is Q-23d-4. That exposed the cast itself. Arrow's parser (ns range, strict grammar) returned NULL with ANSI off for `'2020'`, `'2020-06-01 10:00'`, `'2999-01-01'`, `' 2020-06-01 '`, `'T10:00'` and others, and it read `'… UTC'` in the session zone. Spark answers all of them. 78 of 184 first-pass cells differed.
- **IPI-03 was wider than the brief.** Spark also answers four more shapes, all measured (28 + 8 cells):
  - an empty dynamic source commits nothing;
  - BY NAME mixed lists work;
  - `PARTITION (d = '2024-01-01')` casts to DATE;
  - `overwritePartitions` on transform specs replaces the staged partitions.

  The empty-frame `insertInto(overwrite=True)` in static mode wipes the table.
- **My comparison script only compared error presence.** The OW actor found that R-1 (transform keys) was not equal: RePark refused with a different class. `cmp.py` counted it EQ. Error-class comparison is now in the round briefs.
- **RP-34's `rpd_target_small`.** 24d measured that the fork applies Java's rule exactly; the gap is delete-file bytes (parquet-rs statistics). It is a layout divergence, not a fork bug.
- **IPI-07 needs a fork half after all.** The fork's `TableScanBuilder` has `project_current_schema()`, but the DataFusion static provider always uses the snapshot schema.
- **IPI-06 needs a fork half.** FastAppend writes one manifest under the default spec.
- **IPI-14 `rewrite_data_files`.** The fork's action takes no session writer or snapshot properties.
