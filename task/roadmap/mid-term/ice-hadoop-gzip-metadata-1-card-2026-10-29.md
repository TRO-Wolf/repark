# Card ICE-HADOOP-GZIP-METADATA-1: the hadoop path read follows a stale hint to a deleted row when Java's gzip metadata names are present

**Date:** 2026-10-29. **Filed by:** the second-audit records round (`claude-haiku-5-5`), from the second independent audit of the format-v2 label, findings AUD-007 (Critical) and AUD-010 (Medium) ([the report](../../../docs/audits/iceberg-v2-label-independent-reaudit-2026-10-29.md), section 3).

**Status:** built at `df912dc3` (PR #1218); verification round 1 PASS (Opus 5.5 with four S3 records fixed; Muse MAX zero findings); merges on the owner's word; the charter point is settled: a readable hint naming a missing version keeps Java's refusal (the cleanup case was a probe artefact). Grade A (Opus 5.5 build, with two verifiers: the Opus 5.5 verifier and the standing Muse MAX second verifier, merge gated on the union).

**Why:** ICE-HADOOP-HINT-WINDOW-1 (PR #1205) made the path read of a `type=hadoop` table walk past `version-hint.text` through the plain names `v<N>.metadata.json`. Java's writer can also name metadata files `v<N>.gz.metadata.json`, when `write.metadata.compression-codec` is gzip, and the walk and the listing do not see them. A stale hint then still returns a deleted row: RePark answers ids 1, 2, 3 where Spark answers 2, 3 on the same files. This is the AUD-001 failure class on a narrower trigger, and it is a silent wrong result, which the order's section 1 rule excludes from any carve-out. AUD-010 is the same gap seen as a refusal: a gzip-named current metadata file makes the read refuse with a message that names a plain file that does not exist, and a stale hint into a version removed by cleanup refuses likewise, where Spark answers both.

**Site:** `crates/repark-core/src/iceberg_path.rs`. The function `newest_from_hint` (about lines 125 to 146) probes only the next plain name. The function `metadata_file_version` (about lines 224 to 237) rejects stems with a `.gz` part, so the listing used when there is no hint ignores gzip-named files too. Java's two compressed names are `v<N>.gz.metadata.json` and `v<N>.metadata.json.gz`.

**Fix:** The hint walk and the no-hint listing read the two compressed names as well as the plain ones, with the same walk bound and the same newest-version rule as Java's `HadoopTableOperations.refresh`, so the stale-hint shape answers the newest committed row. The charter settles one point before the build: a hint that names a missing file refuses loud by the AUD-001 fix's design, while Spark answers the newest metadata file. The unit either matches Spark's answer, or keeps the refusal and corrects its message so that it names the compressed name that exists. The owner rules on that point at charter. Pins: one per stale-hint shape on each codec, red on `321c6095`, and the facade pin of the stale-hint read after a committed delete extended to a gzip table.

**Measured (copied from the second audit's hint-walk probe, 18 cases, Spark 4.1.2 on the same files):** `spark_mixed_codec_stale_hint2`: RePark answers `[[1],[2],[3]]`, Spark `[[2],[3]]`, on a table whose newer metadata files are `v3.gz.metadata.json` and `v4.gz.metadata.json` with the hint restored to `2`. `spark_mixed_codec_current_hint` (hint at `4`): RePark refuses with "version-hint.text names 'v4.metadata.json', which does not exist", Spark answers `[[2],[3]]`. `spark_gzip_current_hint` (a gzip table, hint at `3`): RePark refuses naming `v3.metadata.json`, Spark answers `[[2],[3]]`. `spark_cleanup_stale_hint_to_deleted_v2` (cleanup on, hint restored to `2`): RePark refuses, Spark answers `[[1],[2],[3],[4],[5]]`. The hint-missing fallback and malformed hints are Spark-equal and must stay so.

**Retires:** the card when the stale-hint and current-hint shapes on both codecs match Spark on the probe, the refusal shapes are either matched or re-worded to name the file that exists, the pins are green, and the targeted re-audit of this fix passes. The label ledger's AUD-007 and AUD-010 rows (`ice-v2-label-1` C-064 and C-067) then close by citation, and the compressed-codec clause C-007 of the hint-window ledger closes with them.
