# Card F-STRUCT-EMPTY-CHILD-PANIC-1: the fork's reader panics on a struct left with no fields after a column drop

**Date:** 2026-10-29. **Filed by:** the second-audit records round (`claude-haiku-5-5`), from the second independent audit of the format-v2 label, finding AUD-008 ([the report](../../../docs/audits/iceberg-v2-label-independent-reaudit-2026-10-29.md), section 3). This card is the RePark card that the fork ledger's row F2-6 names as "Carded on the RePark side"; before this round no such card existed.

**Status:** open. Grade A. Unit shape: a fork unit (owned `iceberg-rust`), then a RePark repin (RP-63). Not dispatched; awaiting the owner's charter.

**Why:** Dropping the only field of a struct column, then reading the table with `SELECT *`, panics in the fork's reader. The panic is caught at the facade boundary, so the process survives, but the statement fails with a repark internal error where Spark answers a row with an empty struct. The production definition lists panics in library code as a disqualifier, and the fork's current pin is the one RePark reads, so the panic is reachable by ordinary schema evolution. The same panic follows from dropping both fields of a two-field struct, one at a time.

**Site:** the fork's `crates/iceberg/src/arrow/value.rs`, at about line 1056, in `create_primitive_array_repeated`, the arm for a struct type with no value. That arm calls `StructArray::new` with zero child fields. The arrow crate's `StructArray::new` unwraps `try_new`, which refuses an empty field list. The caller chain is `nested_projection::create_constant_column`, then `RecordBatchTransformer::transform_columns`, then `ArrowReader::process_parquet_file_scan_task`. The panic message itself names the constructors that accept an explicit length or empty fields.

**Fix:** The fork builds a struct with no child fields using the row count of the batch it fills, so that each row reads as a non-null empty struct, which is what Spark answers. The arm must not produce a NULL struct for a struct that exists. The fork unit carries its own pins: the drop of the only field then `SELECT *`, the drop of both fields of a two-field struct one at a time, and the empty struct's row count against the batch's. After the fork merges, RP-63 repins RePark, and a Spark-door pin reads the same shapes through the facade with the Spark answer as the expected value.

**Measured (copied from the second audit, reproduced 2026-10-29):** on a table with an integer and a one-field struct, `ALTER TABLE … DROP COLUMN` of the struct's only field succeeds on both engines, and `SELECT id` returns `[1]` on both. `SELECT *` on Spark returns `(1, Row())`. On RePark it raises a `PySparkException` for an internal error, the caught panic reading "called `Result::unwrap()` on an `Err` value" with the constructor error, while the process survives. Dropping both fields of a two-field struct one at a time gives the same panic. The second audit's backtrace run places the panic at the arm named above.

**Retires:** the card when the fork reads both shapes to Spark's answer with no panic, RP-63 repins RePark to the fork merge, the Spark-door pin is green, and the fork ledger's row F2-6 is updated in the fork to cite this card instead of the missing one. The label ledger's AUD-008 row (`ice-v2-label-1` C-065) then closes by citation.

**Relation:** the fork ledger's F2-6 row (`task/f-eqdel-dropped-key-1-ledger.md` in the fork repository, which records the panic as open and cites this card); the parity registry's ICE-NESTED-DDL-1 dated line of 2026-10-29, the `DROP COLUMN` row that the schema-evolution pins sit under; the second audit's gate dimension "schema evolution to empty structs", which the format-v3 gate names as an input.
