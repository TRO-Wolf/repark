## PARITY-LIVE-STOP-1 — no test stops the shared live-oracle context

**Owner, 2026-10-04 morning:** file card PARITY-LIVE-STOP-1 at clerk grade. "The fix is the
live-cell rule (guard the shared session, never stop it), nothing more. Not a release item."
The owner named `test_ice_meta_delete_1.py`, whose module fixture calls `session.stop()`
(line 131).

### Why

- **What runs:** `parity-live.yml` runs `pytest python/repark/tests` every night with `REPARK_PARITY_LIVE=1`, against one shared PySpark context.
- **The guard:** `_shared_oracle_context_guard` in `python/repark/tests/conftest.py` fails a test when it finds that context stopped or replaced. It also fails when no PySpark session is active.
- **The cascade:** the guard checks after every test, so once the context is gone, every later test fails or errors.
- **NIGHTLY-LIVE-1** (#505, `6fa17a47`) fixed the previous red stretch, 2026-09-05 to 2026-09-11.

## SOURCE-URL-REDACT-1 — a password inside a URL-shaped property value is never displayed

**Owner, 2026-10-06 ~06:25 EDT:** "Yes go ahead immediately, we need security to be tight."
A security fix to main that ships in v1.5.3. Branch `fix/source-url-redaction-1`; ledger
[source-url-redact-1-ledger.md](../../ledgers/staging/source-url-redact-1-ledger.md).

### Security (release-note line; no v1.5.3 notes draft exists yet)

- A password embedded in a URL-shaped source or catalog property (for example
  `url = "postgresql://u:pw@h/db"`) was shown in plain text by `sources()` and the config dump
  since v1.4.1; it is now masked.
- Fold 1 (same unit): the same masking now covers table and view property displays
  (`DESCRIBE TABLE EXTENDED`, `SHOW CREATE TABLE`, `SHOW TABLE EXTENDED`, `SHOW TBLPROPERTIES`)
  and configuration refusals, and `SET` redacts with Spark 4.1.2's default regexes (`url` and
  `access[.]?key` included).
- Fold 2 (same unit): Oracle `user/password@host`, a password containing `@` inside a query or
  `;`-property, whitespace inside a URL password, JSON and YAML values, the `passwd` / `pass` /
  `pw` / `passcode` / `AccountKey` names, and Azure account-key, `Authorization` and `pat`
  settings are now masked too, as are the `DESCRIBE NAMESPACE` rows and option refusals.
- Fold 3 (same unit): `SHOW TBLPROPERTIES` of a table or view, `SHOW CREATE TABLE` of a view
  and every other property display now redact secret-keyed properties (shown as
  `*********(redacted)`), at least where Spark 4.1.2 does; Oracle TNS-descriptor passwords and
  multi-line YAML/JSON secrets are masked; credential-free storage paths such as
  `s3://lake/data@corp.example.com/ns` are shown unchanged again, and
  `spark.catalog.getDatabase(...).locationUri` returns the stored location.
