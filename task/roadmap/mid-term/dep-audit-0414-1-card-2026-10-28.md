# DEP-AUDIT-0414-1: RePark's configured `cargo audit` is red on RUSTSEC-2026-0414 through a build dependency (RePark card)

**Filed:** 2026-10-28. **Filed by:** the audit clerk round (`claude-haiku-5-5`), from the independent audit ([iceberg-v2-label-independent-audit-2026-10-28.md](../../../docs/audits/iceberg-v2-label-independent-audit-2026-10-28.md)) and the orchestrator's reproduction of 2026-10-28.

**Status:** closed. Merged 2026-10-29 as `e7135000` (PR #1210): `pulldown-cmark` 0.13.5, a two-line `Cargo.lock` change. RUSTSEC-2026-0414 is cleared and the scheduled audit check is green again on main.

**Grade:** not graded yet. A dated ignore entry needs the owner's word; a lock bump does not.

**Severity:** P3. A dependency gate result, not a proved runtime defect. The audit found no exploit and did not establish the affected feature in RePark's build.

## Why

RePark's configured `cargo audit --json` on main fails with exit 1 on RUSTSEC-2026-0414 (pulldown-cmark 0.13.4, the advisory concerns `ENABLE_WIKILINKS`). The lockfile reaches it through `prost-build`, a build dependency. It was absent from the audit's inspected active native dependency closure. The earlier green CI run predates the advisory database revision the audit used. The three zstd advisories (RUSTSEC-2026-0391, 0398, 0403) stay policy-ignored in `.cargo/audit.toml` (lines 21 to 33) and `deny.toml` (lines 35 to 56); the same lockfile audited outside the repository configuration exposes them with 0414 and pre-existing quick-xml entries.

## The fix

Either bump the locked `pulldown-cmark` (or the `prost-build` path that pins it) to a patched version, or add a dated ignore entry with its reachability reasoning, which the owner must accept. The lock bump is preferred if the build dependency moves cleanly. Use a clean git merge and `cargo metadata --locked`; a bare `cargo update -p … --precise …` can re-point duplicate edges.

## Pins

- `cargo audit` exits 0 on main under the repository configuration, with the three zstd entries still ignored by their dated policy.

## Out of scope

- The zstd advisories themselves (the policy entries stay as they are).
- The fork's audit on the fork's own lock; it is a fork matter.
