## 3. What the measurements showed

- **The fork prune conversion was unsound in five places, not one.** Critic F-01 (21a) was the float-underflow case.
  Today's logic critic built four more failing `DELETE` statements, each with deleted = 0 where 1 was expected:
  `CAST(f AS INT) = 2` over `2.5`; `f = Inf` over `+Inf` (the AboveMax sentinel folded to AlwaysFalse); `f <= -0.0`;
  and `f != NaN`. Those were the premises. The actor and then the verifier measured that this DataFusion build
  compares floats in **total order** (`0.0 <= -0.0` false, `NaN = NaN` true, `f != NaN` false on a NaN row). That
  makes the last two conservative hardening rather than live misses. The first two were real silent misses.
- **ARRAY inserts, end to end.** RePark main was built against the fork branch (a local override, never committed).
  `writeTo().append()`, `insertInto`, `saveAsTable(append)` and `INSERT … SELECT` of `list<int>` then answered Spark's
  rows. `INSERT … VALUES` still failed from a second site: DataFusion's VALUES planning against the provider's
  field-id-stamped schema. The first fix (strip the advertised schema) then broke DataFusion's physical-vs-logical
  schema check (fork CI `insert_distribution` ×3). Round 4 settled on one advertised schema: top-level ids kept,
  nested metadata stripped, and the scan emitting the same shape.
- **Spark oracle for ARRAY inserts.** 30 cells: `list<int>`, `list<struct>` and `map<string, list<int>>` × five doors ×
  v2/v3. All accept, and every parquet footer carries the element, key and value ids. File
  `/tmp/oc-worker/la-oracle/array_insert_truth.json`, recorder `record_array_insert.py`. These are ready for the RePark
  pins once #295 is bumped.
- **RePark's CREATE refuses `ARRAY<STRUCT<…>>` and cannot parse `MAP<…>`**, not even `MAP<STRING, INT>`
  (`ParserError … found: <`). Those shapes are reachable only through Spark-created, adopted tables. This is 22b's
  nested-DDL area (#695).
- **#294's L-04 drop surfaced two RePark plan-shape pins** (`nan_inequality_pushes_not_nan`,
  `nan_single_not_in_pushes_not_nan`). They were red in #702's CI and are flipped to "pushes nothing". The answers
  still come from the residual, and the oracle-set pins stayed green.
