# Crate layout review — 2026-09-30

**Filed:** 2026-09-30 by a Claude session (claude-fable-5-1) on the owner's question of 2026-09-29:
can the directories that hold only a `tests.rs` be avoided, and could the crates be organised more
like Polars, DataFusion or Sail? This is a review with options; nothing was changed. The published
page is [docs/artifacts/crate-layout-review-2026-09-30.html](../../../docs/artifacts/crate-layout-review-2026-09-30.html).

RePark measured on `origin/main` at `adc26586` (2026-09-28). Sail, Polars and DataFusion measured from
their GitHub default-branch file listings on 2026-09-29; DataFusion 54.1.0 also inspected from the
cargo registry.

## The short version

The `foo.rs` plus `foo/tests.rs` pattern is the smallest part of what separates RePark from those
three projects. What separates them is that they keep most behaviour tests out of Rust files:
DataFusion in 526 `.slt` files, Sail in 87 gold-data files and 237 Python test files, Polars in 467
Python test files. RePark holds 53 % of its Rust lines as tests, and the directory pattern is a
symptom of that volume.

The three reference counts come from file listings only, so their test share by lines is unknown.
RePark's Python facade suite was not counted here either; the comparison is about where Rust-side
behaviour tests live.

- **DataFusion** puts one function per file under a category directory
  (`functions/src/string/upper.rs`), writes unit tests inline (69 of 120 files in
  `datafusion-functions` 54.1.0 carry a test module, none has a `tests.rs`), and groups integration
  tests into a few binaries with submodules (`core/tests/core_integration.rs`). Statement-level
  behaviour lives in `.slt` files run by `sqllogictest`.
- **Polars** keeps one integration binary for the umbrella crate (`polars/tests/it/main.rs`) and one
  crate-level test tree (`polars-lazy/src/tests/`, 14 files). Behaviour is tested from Python.
- **Sail** has no Rust test trees at all: 3 integration binaries across 38 crates. Behaviour is
  pinned by gold-data JSON under `sail-spark-connect/tests/gold_data/` (recorded answers,
  regenerated by an environment flag) and by a Python suite.

Lines are counted with blank lines, the way the file-size gate counts them. "Inline" is the tail of
a product file from its `#[cfg(test)] mod … {` to the end; "out-of-line" is every file named
`tests.rs`, `*_tests.rs`, or sitting under a `src/**/tests/` directory.

### Three placements are in use at once

- **Inline test modules** in 230 product files, about 45k lines.
- **`foo.rs` plus `foo/tests.rs`**, declared with `#[cfg(test)] mod tests;` in 80 files. This gives
  the 36 directories that hold one file and one `map.md`. Those maps are not empty: with code
  comments banned, `na_fill/map.md` is where the module's purpose and its `pins:` citation live.
- **Crate-level `src/tests/` trees** in 11 places, 246 files. `repark-spark/src/tests/` alone is 161
  files, 85,604 lines and 1,875 tests; 147 of those files run SQL through a session helper. They
  reach crate internals with `use super::super::*`, so they are unit tests by visibility even though
  they read like integration tests.

The second pattern has precedent: from memory, the Rust standard library enforces it with a tidy
check. The unusual part is carrying a directory and a map for one file.

### The crate roots are flat

`repark-spark/src` has 61 files and 18 directories at its root; `repark-functions/src` has 77 files
and 25 directories. DataFusion groups functions by category and Sail's function crate by kind
(`scalar`, `aggregate`, `window`). RePark's roots mix DDL, DML, casts, literals and routing at one
level.

### Integration binaries are unconsolidated

`repark-sql` has 24 top-level files under `tests/` and `repark-spark` 9. Cargo links each one as its
own binary against the whole engine. The run-21 freeze on this machine came from 89 concurrent
`rust-lld` processes; the number of test binaries is one of the multipliers.

## Options, cheapest first

### 1. One integration binary per crate (measured)

- Shape: Polars' `tests/it/main.rs` with one module per former file, or DataFusion's
  `core_integration.rs` declaring `mod sql; mod dataframe;` and so on.
- Gain: 45 link steps become about 8. Shared fixtures stop being copied per binary.
- Cost: every `cargo test -p … --test cross_door` in briefs, gates and CI changes to a filter.
  Mechanical otherwise.

### 2. Remove the single-file test directories (rule)

- Shape: the only way to keep a child test module out of a directory is
  `#[cfg(test)] #[path = "na_fill_tests.rs"] mod tests;` next to `na_fill.rs`.
- Blocker: [AGENTS.md](../../../AGENTS.md) rules this out ("Rust module layout is the default one …
  `#[path = "…"]` is not module inclusion: move the file into the canonical tree"). One `#[path]`
  use exists in the tree today.
- So: removing the 36 directories needs an owner decision to carve a test-module exception into
  that rule. Without it, the alternatives are to leave them, to fold each `tests.rs` into its
  crate's `src/tests/` tree (which widens private items to `pub(crate)`; 59 of the out-of-line
  files reach parent internals through `super::`), or to move the tests back inline (which the
  file-size gate then counts against the product file).

### 3. Group the flat crate roots by family (judgement)

- Shape: `repark-spark/src/{ddl,dml,cast,literal,router,…}/`;
  `repark-functions/src/{datetime,string,math,…}/`, the DataFusion arrangement.
- Gain: a reader or an agent finds a family in one directory instead of a 79-entry listing. No
  crate-graph change.
- Cost: every moved file changes its `map.md` rows and its `pins:` citations, and the file-size
  `EXCEPTIONS` table is keyed by path. Test filter names derive from module paths, so gate filters
  change too. Do it one family at a time.

### 4. Move statement-and-answer tests into data files (judgement)

- Shape: DataFusion's `.slt` or Sail's gold JSON: a statement, the recorded answer, and a harness
  that runs both engines. RePark already records Spark answers as JSON oracles for the Python
  suite; this brings the same shape to the Rust side.
- Gain: this is what makes the reference projects look the way they do. A behaviour test is a row
  in a data file, so it does not count against any `.rs` ceiling, cannot bloat a module, and is
  recorded from Spark rather than written by hand. It also fits the Rust-first ruling: the harness
  is Rust, the cases are data.
- Cost: a harness to build and a corpus to migrate. Tests that assert on Iceberg metadata (snapshot
  summaries, manifest counts, as in `src/tests/truncate.rs`) do not fit a statement-and-answer
  format and stay in Rust. Only 147 of the 161 `repark-spark` test files are candidates, and each
  needs a reading before it moves.

### 5. More crates (judgement)

Sail and DataFusion have four times RePark's crate count. A split of `repark-spark` or
`repark-functions` would follow the family grouping of option 3, not precede it, and
[ARCHITECTURE.md](../../../ARCHITECTURE.md) fixes the crate DAG. Not opened now.

## What any move has to carry (measured)

- `scripts/check_rust_file_size.py` keys its `EXCEPTIONS` table by path and fails closed on a path
  that no longer exists; the current table has rows for test files (`dynamic_flatten/tests.rs` at
  1,442, `catalog/tests/catalog.rs` at 1,843).
- Every directory carries a `map.md`, checked for lockstep in the same commit, and
  `pins: unit/C-NNN` citations live in those maps, so a moved test moves its citation.
- Briefs, gates and CI name test paths and `cargo test` filters. A rename silently narrows a filter
  unless the filter is updated.
- Relocated code sheds its comments under the comment gate, which is no cost for tests already free
  of them and a review duty for the rest.

## Recommendation

1. After v1.5.1 ships, do option 1 (integration binaries) as one mechanical unit per crate,
   starting with `repark-sql`.
2. Put option 2 to the owner as a one-line rule question: allow `#[path]` for a `#[cfg(test)]`
   child module and nothing else, or keep the directories. Either answer closes the question.
3. Pilot option 4 on one statement family (`repark-spark/src/tests/call_*.rs` is a contained set)
   before deciding whether to migrate more. It is the only option that changes how tests are
   written, and the only one that moves RePark toward the reference layouts rather than tidying
   within the current one.
4. Take option 3 family by family behind the pilot, when a family is next touched.

## What was not verified

- The reference projects were measured from file listings, not checkouts; nothing about their line
  counts or test share is claimed.
- The standard-library precedent for `foo/tests.rs` is from memory.
- The 147-of-161 candidate count for option 4 is a grep for a SQL call through a session helper,
  not a reading of each file.
- No build or test was run for this review.
