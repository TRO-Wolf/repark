# DEPS-1 — the zstd 0.14 bump behind the datafusion release

**Filed:** 2026-10-26 by the clerk round on the zstd advisory brief. **Status:** open — the three
advisory ignores are in place (`deny.toml`, `.cargo/audit.toml`); the bump waits on upstream.
**No code in 1.5.x beyond the ignores.**

## The facts (measured 2026-10-26)

Three RustSEC advisories published against the zstd family turned the `cargo-deny` gate red on
every pull request; main's own run of the gate was green at `ab1b9bc8` on 2026-10-25.

- RUSTSEC-2026-0391, crate `zstd`: data from an abandoned stream leaks into the next stream on a
  reused context (an encoder dropped before `finish()` after an error). Patched `>= 0.14.3`;
  unaffected `< 0.13.2`. This tree ships `zstd` 0.13.3.
- RUSTSEC-2026-0398, crate `zstd-safe`: `Seekable::decompress` sets a `Vec` length beyond its
  capacity for offsets past the end. Patched `>= 8.2.0`. This tree ships `zstd-safe` 7.2.4.
- RUSTSEC-2026-0403, crate `zstd-safe`: uninitialized memory exposed when streaming
  decompression of a legacy frame fails. Patched `>= 8.2.0`.

Why the bump cannot be taken: `cargo tree -i zstd@0.13.3` shows nine dependents pinning the
0.13 line: `parquet` 58.4.0, `arrow-ipc` 58.4.0, `datafusion` 54.1.0, `datafusion-datasource`
54.1.0, `apache-avro` 0.21.0, `orc-rust` 0.8.0, `compression-codecs` 0.4.38, the owned Iceberg
fork `iceberg` 0.9.1 (rev `d80a2884`) and `repark-core`. Upstream today: parquet and arrow
60.0.0 are on zstd 0.14; datafusion 55.2.0 (latest) still requires `^0.13`; apache-avro 0.22.0
and orc-rust 0.9.0 still `^0.13`; the fork follows datafusion. The patched line becomes
reachable only when datafusion releases against arrow 60, then the fork is repinned (an RP
unit), then zstd moves.

Reachability: the seekable API (RUSTSEC-2026-0398) is referenced by none of the six zstd-using
dependents' sources (grep of parquet, arrow-ipc, apache-avro, orc-rust, compression-codecs,
datafusion-datasource: zero files). For RUSTSEC-2026-0391 and RUSTSEC-2026-0403 reachability
from this tree is NOT established; that is stated, not softened, in the ignore entries.

## The trigger

The datafusion release on arrow 60, then the fork repin, then the zstd bump. The ignores come
out in the same pull request as the bump — never earlier.

## The steps (each clerk grade)

1. **Datafusion bump unit:** move the tree to the datafusion release built on arrow 60, through
   the version-pin contract (`Cargo.toml` SSOT, `cargo update`, the fork duties re-verified).
2. **Fork repin RP unit:** repin the owned `iceberg-rust` fork past the datafusion move, with the
   fork's repin duties from `crates/repark-iceberg/map.md`.
3. **zstd bump:** take zstd to the patched line and remove all three ignores from `deny.toml`
   and `.cargo/audit.toml` in the same PR, with `cargo deny check advisories` green without them.

## Weekly check

Until the trigger fires, check weekly whether datafusion has released against arrow 60; record
each check here as a dated line (take/skip per the version-pin contract). First check due
2026-11-02.
