## 3. What the measurements showed

- **The bed caught two gaps in its first hour.**
  - `count(*)` read every footer (C-9).
  - A Spark-door `CAST(n AS TIMESTAMP)` filter never reached the Iceberg scan: `predicate:[]`, 200 footers, 65.5 MB of pages for a 1 % window.
  - The second gap went to 24b as F-TS-PUSHDOWN-1 (fork #312) and is fixed on main.
- **C-9 root cause.** RePark's `SparkIntegralLiteral` / `SparkIntegerLiteral` narrowed count-star's `Int64(1)` to `Int32(1)`, so DataFusion's `Count::value_from_stats` never folded over the fork scan's `Rows=Exact`.
  - The fix (#721) worked: warm 200 footer reads → 0, 12.4 → 3.2 ms.
  - CI then showed the fold answering **0** after MoR MERGEs → `rewrite_position_delete_files` → `rewrite_data_files`. The fork's `replace` snapshot summary says `total-records=0, total-data-files=0` while the table holds 1,000 rows. That is wrong metadata on main today, visible in `t.snapshots`.
  - Fork asks: F-RDF-SUMMARY-1 (24d) and F-EXACT-COUNT-1 (24b #317: sum the manifests' record counts, as Java does).
  - The unit's Grok critic had passed it. CI's facade suite caught what the critic missed.
- **Footer reads.** Each footer read is 512 KiB, one per file per scan. On split files (> 65,536 rows, 8 writers) the same footer is read twice. The footer cache removes both: warm 200 → 0, and cold split files 40 → 20.
- **Page pruning** (RePark-written files):
  - RePark's writer rolls an INSERT across eight writers above 65,536 rows. Ordinary files therefore carry about 4 pages per column, which leaves page selection little to skip.
  - On the 25-page large bed it trims the point and window lookups by about 10–17 %.
  - It costs CPU on predicates no page can prune (Q6 +18–20 % on the 200-file bed); 24b's fork #319 (F-PAGE-PRUNE-2) addresses it.
- **Spark's `rewrite_table_path`** (1.11) leaves a stale `file_size_in_bytes` on rewritten position-delete files. RePark refused such a table until fork #310's footer retry; now it answers.
- **The re-measure gate** (unit 4, local beds): see the table below. The AWS bed was never reached (§5).
