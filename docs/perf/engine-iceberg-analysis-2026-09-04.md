## 4. Unmeasured hypotheses (no isolating fixture yet — not reportable as candidates)

- **MERGE MoR residual.** MoR MERGE upsert is 520–612 ms while its measurable phases sum to ~280 ms (discovery join 57, insert anti-join 52, one-file rewrite join 28, matched-work join ≤ 166); the remaining ~300 ms is the DV close + commit + per-file `fsync` (py-spy: `fsync` 7 % of samples) — Spark's MoR MERGE is 390 ms (1.6× faster), COW MERGE 776 vs repark 651. Needs a tracing-span instrument (`merge.join` / `merge.write_data` / `merge.commit` spans exist but no subscriber is installed from Python).
- **`fsync` per data file on local FS.** `LocalFsFileWrite::close` fsyncs every file (5.8–7 % of write samples). On S3 this does not exist; on local warehouses it is a knob candidate.
- **`sum(f64)` 1.9× and `groupby_cat` (Utf8View keys) 2.2× DuckDB** on the plain parquet path — no fixture pair isolates the kernel from the scan.
- **Iceberg Utf8View → Utf8 cast before writing** (`cast_view_to_byte` 1.5 % of CTAS samples): the writer casts DataFusion's view strings back to `Utf8`.
- **Glue latency multiplication.** Candidate 11's call counts × a Glue `GetTable` round trip; no per-call AWS timing is recorded anywhere (only `6 passed in 122.13s` / `4 passed in 145.15s` suite walls in `docs/tier2-aws.md`). Whether `plan_files` reads S3 manifests concurrently (it uses channels sized `num_cpus`) is not measured.
- **F-26 (fork `#267`) is not consumed** at this pin (`189a73ed`); it hands partitions to the DV close on the in-tree DataFusion MoR DELETE/UPDATE path (fork-claimed 685 → 10 ms at 192 manifests). RePark's plain `DELETE … WHERE` now goes through `predicate_dml/plain.rs`, so the benefit on RePark's path is unknown until a repin measures it.
- **TPC-H Q1 4.8× DuckDB** (`WRONG-RESULT` on the decimal `avg` type, Z-3 U1): the Q1-like pair here (decimal 138 ms vs double 121 ms; DuckDB 64 / 82) says decimal arithmetic is not the cause; candidate 10's `avg` accumulator (7 aggregates, 4 groups) is the likelier one — unmeasured on Q1 itself.
- **Spark `toPandas`/`toArrow` asymmetry**: Spark pays a JVM→Python transfer (197 ms at 1e6) that repark does not (24 ms); every Spark ratio above includes it (dynflatten do-not #4).
- **`insert_into` fixed cost decomposition** (33 ms for 100 rows): 5 `metadata.json` + 3 manifest-list + 2 manifest opens + one data file + one manifest + metadata write with `fsync`; which of these dominates is not split.
