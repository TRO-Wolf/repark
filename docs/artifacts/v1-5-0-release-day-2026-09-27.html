AWS acceptance

It had been red every night since 2026-09-19, and always on the same test: test_create_or_replace_twice_against_s3tables, where S3 answered 412 ConditionNotMatch. The cause was fork rp-26, which wrote a replace's metadata file at begin and rewrote the same key at commit. S3 table buckets refuse the overwrite; Glue buckets and local stores accept it. The chain from there:

  • A Muse round reproduced the failure locally.
  • Fork #362 fixed it.
  • #872 repinned RePark to the fixed fork and added a regression pin that fails at the old pin and passes at the new one.

Live confirmation: the scheduled run on 2026-09-28 (run 36400422783, main abdeae41) passed 10 of 10, including test_create_or_replace_twice_against_s3tables, plus dbt gold 1 of 1. It is the first green nightly since 2026-09-18. green
