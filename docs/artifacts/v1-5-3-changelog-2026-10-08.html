Security

Credentials are never displayed

Since v1.4.1, a credential embedded in a URL- or DSN-shaped source or catalog property was shown in plain text by sources() and the config dump. Three fixes close that and the paths around it.

  • Displays are masked. DESCRIBE TABLE EXTENDED, SHOW CREATE TABLE, SHOW TBLPROPERTIES, DESCRIBE NAMESPACE, the config dump and SET all redact. Secret-keyed properties show as *********(redacted), at least where Spark 4.1.2 does.
  • Errors are masked. Every Python-visible error masks URL userinfo, including message parameters and the chained copy of a re-raised error.
  • Non-URL shapes are covered. JDBC query strings, libpq keyword strings, ODBC connection strings, Oracle and TNS logins, JSON and YAML values, and Azure account-key, Authorization and personal-access-token settings.
  • User-code errors are masked too. Errors raised inside UDFs, pandas and Arrow UDFs, UDTFs, applyInPandas, applyInArrow, mapInPandas and mapInArrow.
  • Nothing else changes. Text without a credential is unchanged, byte for byte. Credential-free paths such as s3://lake/data@corp.example.com/ns display as stored.

Two known limits. An exception class with its own __str__ is not rewritten. foreach, foreachPartition and transform pass the user's own exception through unchanged.

Behaviour change

Attribute identity: ambiguous self-joins now raise, as in Spark

Columns now carry Spark-style attribute ids. This is the one change in the release that can turn working code into an error, and it does so only where Spark Classic raises too.

s = d.select("id")
s.join(d).select(d.v)

v1.5.2

Answered d's v, four rows.

v1.5.3 and Spark

Raises _LEGACY_ERROR_TEMP_1182, with Spark's message word for word.

The same holds after any join whose two sides share lineage: a select, filter, groupBy, orderBy, withColumn or aggregate over a column bound before the join raises when Spark cannot tell which side it points to.

The fix in your code

Alias the frames and reference the alias, as Spark's own message suggests. The join is unchanged; only the reference changes.

s.alias("a").join(d.alias("b")).select(F.col("b.v"))

Spark's switch spark.sql.analyzer.failAmbiguousSelfJoin=false turns the check off, and references then resolve by id. It is not a return to the old answers.

Also newly raising

  • Two reads of a DataFrame view joined to each other: spark.table("tv") twice, then select(left["v"], right["v"]).
  • A cross-field self-join condition, d.join(d, d.id == d.v). v1.5.2 answered an empty frame.
  • Under caseSensitive=true, a wrong-case name in select, df[...], fillna or dropDuplicates. withColumn("VAL") now appends where v1.5.2 replaced.
  • Writing duplicate display names to parquet, json, orc, saveAsTable or writeTo refuses with Spark's COLUMN_ALREADY_EXISTS before any file is created.

Newly answering

  • Aliased joins with qualified references: .select("l.v", "r.v") after d.alias("l").join(o.alias("r"), ...). v1.5.2 raised UNRESOLVED_COLUMN.
  • withColumnsRenamed to duplicate names.
  • A sort over exact-duplicate projection outputs, answered by the source column.
  • Self-joins whose two sides carry the same column names. Internal twin names never reach files, tables, views or Arrow and pandas exports.
  • freqItems, describe and transpose frames now write Spark's column names.

What it cost

The stack merged after meeting its performance gate: 1.0812× of pre-stack main on the work-equal replay set, release builds, median of three, against a 1.10× ceiling.

Performance

TA indicators on one long series

Eighteen TA calls over one million rows of a single series, in three dependent withColumns levels. Release wheels, median of five, interleaved with polars_talib in one process on a 64-core box.

  • A bare ta.* column is a series. Without .over(...) it is computed over the frame's declared sort order. With no declared order, the first timestamp column orders the series and RePark warns once per session. Before this change the answer depended on the order a split read delivered.
  • Order is kept. A sorted single-partition frame read back through .eager(), .cache() or localCheckpoint keeps its order on plain reads.
  • One partition runs in parallel. Independent window expressions and projections on a single partition run side by side, up to repark.target.partitions.

For one series per instrument, keep using .over(Window.partitionBy(...).orderBy(...)).

Fixes

Smaller fixes

  • The v1.5.2 slowdown is repaired. v1.5.2's deep-chain fix grew the stack at 34 native call sites on every call, which slowed ordinary work by about 5.2%. The stack now grows only when the query is deep. Answers are unchanged and deep chains still answer.
  • ANSI division by -0.0 raises DIVIDE_BY_ZERO, as Spark 4.1.2 does. A NaN divisor still answers.
  • The nightly live-parity suite is readable again. A test was stopping the shared Spark context; the suite now reads 4 failed and 0 errors, down from 156 failed and 7,565 errors.

Upgrading

From v1.5.2

pip install --upgrade repark==1.5.3
  • Search for joins where both sides come from the same frame and a later step references a pre-join column. Those are the ones that can now raise 1182. Alias both sides.
  • If you write frames with duplicate column names to parquet, json or orc, rename first.
  • If you call bare ta.* without .over(...), sort the frame by its time column first so the series order is yours and the one-time warning does not fire.
  • If any tooling parsed credentials out of sources(), the config dump or error text, it now sees masked values.
