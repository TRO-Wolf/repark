RePark · project review · 9 November 2026

The measurement works. The plan does not yet predict the next defect.

RePark's live Spark oracle and domain tables find real defects, including two that would have written wrong data. The project still finds each Spark difference one family at a time, after release, and spends more on review rounds and records than on fixes.

Evaluation

What is working

  • The live Spark 4.1.2 oracle and the domain tables find defects that review alone missed: the empty-DML wipe and the struct comparison.
  • An independent clerk table corrected the planner's own probe within hours. The table-first rule did its job.
  • Owner rulings are recorded verbatim and briefs carry them.
  • Mechanical work goes to cheap tiers, and scratch clones keep the live tree safe.

What is not

  • Discovery is bottom-up. Each Spark difference is found by probing cells, one family at a time, usually after a release.
  • Review costs more than building. Unit C and #1267 both failed review because rule seats and entry doors were found after the build.
  • Records outweigh fixes by about three to one in merged pull requests.
  • The owner's decisions are mostly latency. Tables of six to twelve questions are answered "defaults" several times a day.
  • Parked work accumulates and drifts from main.

On the planning session itself. The Step 4.1/4.2 evaluation found the shipped defect and the fix shape held up. Two cells in its defect table were wrong: one result came from running three DML statements in sequence on one table, and one Spark result was derived from a SELECT and written as if it had been run. The probe rules from now on: one fresh table per DML cell, and any Spark column not run on Spark is labelled as derived.

Seven changes to how the work runs, in order

  1. Audit the coercion seam from the top down

    List every entry point in DataFusion's type coercion (comparison, struct, set operation, CASE, function signature) and classify each against Spark's rule once. The result is a finite list of the next defects, known before they ship.

  2. Give the analyzer rule list one home

    Rules are seated in three places today. One seating function, and a test that every session context is built through it, turns the insertion inventory from a duty in each brief into a gate.

  3. Gate releases on wrong writes

    No tag while a card rated S1 with DML reach is open, unless the release notes name it. This gate would have caught 1.5.6.

  4. Replay every domain table nightly as one number

    A count of cells that differ from Spark, by class, that trends over time. It tells the owner where the product stands without reading a ledger.

  5. Delegate the decisions that are not decisions

    Standing authority for green docs-only merges, card filing and severity ratings. The owner keeps release go or no-go, semantic divergences and spend.

  6. Triage the parked pull requests

    Close each with a pointer card, as on 19 October. #1267 closes when the comparison carve lands.

  7. Prune the shared agent memory index

    It is over its size limit, so the newest entry is dropped when a session loads it. Old rulings move to the archive file.

The guidance documents

PROJECT.md is the strongest of the set. Its priority order, its semantic precedence and its definition of production-grade are clear and usable. The problems are around it: the documents disagree with each other, STATUS.md does not show the present, and the plan the agents follow is not in the repository.

Seven changes to the documents, in order

  1. One release table in one home

    Rewrite the release roadmap as a single table: release, its one outcome, the card that defines acceptance, and its state. Move the renumbering history to an archive file. PROJECT.md then points at the table and drops its own copy.

  2. STATUS.md opens with the present

    Today it says "Release blockers: None", its correctness section opens with debt carried from the August port, and the shipped struct-comparison defect is not in it. Open the file with a short board: the shipped version, every open S1 and S2 with write reach, the label states, the unit in flight and the next three. Move the history below or out.

  3. Bring the plan and the rulings into the repository

    The step sequence and the owner's rulings live in planning files outside the repository and in one tool's agent memory. Agents on other tools cannot read them. Keep one tracked plan file of the current sequence, and one tracked rulings ledger with a row per ruling: date, id and the owner's words. The sequence file in briefs/ was opened on 21 August and can retire into it.

  4. Give the 1.5 line an exit

    Its outcome was met on 27 September at 705 equal cells and none different. Six patch releases followed and the format-v2 label was withdrawn, because the 842-cell matrix does not measure expression semantics inside DML, which is where the defects are. Define the label as a finite checklist: the coercion seam classified, the domain tables replayed with no wrong write and no wrong answer, and the real-workload run. Set a budget, after which what remains becomes a declared divergence and the line closes.

  5. Put a meter on the headline claim

    PROJECT.md says RePark replaces Spark in production ETL, and year one serves the operator's Airflow, Iceberg and dbt workloads. The cutover inventory was filed on 4 September. STATUS.md reports cells and labels, not pipelines. Add a cutover scoreboard: of the inventory's workloads, how many run on RePark in shadow, in canary and in production. Among defects of equal severity, the one that blocks a listed workload goes first.

  6. Give cards fixed fields and a generated index

    Status lines are free text and the folder also holds day reports and release notes. Fixed fields on each card (severity, write reach, door, release line, state) let a script print the open backlog by release and feed the release gate.

  7. Add one principle to PROJECT.md, and trim three passages

    The principle: behaviour inherited from DataFusion is unmeasured until it is classified against the door's reference. It would have predicted the struct defect. The trims: the release history inside the first goal, the table of current offenders in the legibility section, and the 16 August validation roadmap, which has no release mapping. Add outcome lines for 1.9 to 1.13 so the server and the distributed destination have a stated path.
