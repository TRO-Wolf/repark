A read-only Opus evaluation of RePark's write-path crate boundary against Sail, on RePark main a556289d and Sail upstream main d219a985 (pulled this morning, 66 commits past v0.7.2). Nothing was built or edited in either tree.

The layering is not the cause, so no crate redesign. The three nested store sites come from six write doors that each build their own store projection; the doors that let the DataFusion plan do the cast already get the rule right in one place. Sail has the same crate gap and does not suffer from it, because every conversion is one plan-time projection built in its Spark-semantics crate and the format crate receives a plan already in table types. The recommendation is option D: copy that one plan-time stage inside the existing graph, with no new crate and no new edge, in four steps split around the v2 label.

The premise of this morning's card was wrong, in a useful way

The WRITE-SPINE-1 card said the three store sites in the Iceberg crate "cannot call" the seam helper because that crate depends only on the common crate. Three facts from the code undercut that:

  • The Iceberg crate already runs at plan time. It registers two analyzer rules and builds SQL text for assignments, so a plan-time stage can live there today.
  • It already reaches the functions crate's kernels by name through the session's function registry. The store-kernel lookup in ntz_store.rs does exactly that. No crate edge is needed to call the seam kernel the same way.
  • Two of the three sites have the session zone in scope. Only the batch cast at the sink does not, and once the other two conform at plan time, that one becomes the identity.

One defect fell out of that reading: when the registry lookup finds no kernel, the code falls back to a plain cast that reads the wall as UTC, silently. Step 1 below makes it refuse instead.

Option D, in four steps

  1. Before GATE-RETIRE-1, no stored value changes. Move the five function names that both crates define as separate string copies into the common crate. Make the store-kernel lookup fail closed. Disjoint from GATE-RETIRE-1's files.
  2. After ZONE-SEAM-1 and GATE-RETIRE-1. Merge the two existing plan-time store functions into one conform function that covers nested columns through the seam kernel, and route the six self-projecting doors through it. The sink's batch cast becomes the identity on every door but the native v3 create, which stays as the control.
  3. Before GATE-RETIRE-1. Generate the door matrix test from the router's statement arms and the write-option flags, so a door that skips the stage fails a pin. This also makes GATE-RETIRE-1's verification mechanical.
  4. After the v2 label of 11-10, before v3 on 11-17. Retire the ZS-9 refusal and the R-011 cast arm with dated rows. ZS-9's over-refusal is honest and labelled, so the v2 label does not need this step.

WRITE-NTZ-TO-LTZ-NESTED-1 becomes step 2 of this plan rather than a unit of its own.

Where the docs and the code disagree

  • ARCHITECTURE.md says ten crates and lists the connect crate as pre-declared with no directory; the workspace has eleven and the connect crate is built and depended on. Fixed in the record PR.
  • The crates map calls the functions crate a leaf with no internal dependencies; it depends on the common crate and on the fork's Iceberg crate. Fixed in the record PR.
  • ARCHITECTURE.md calls the Iceberg crate a thin adapter; its write directory holds about 4,500 product lines of Spark store-assignment semantics, two analyzer rules and seven store kernels. Left for you to reword.
  • ARCHITECTURE.md says the native door refuses INSERT OVERWRITE; it executes the PARTITION forms and refuses only CALL. Left for you.
  • The streaming micro-batch sink bypasses every router rule: no zone, no gate, floor by refusal only. A parity gap, now in the door table.

What was not measured

  • Door paths are by reading; the assignment of doors to the three sites comes from the seam's instrumented build.
  • Sail's write-time zone and nanosecond behaviour are by reading; Sail was not run.
  • The UPDATE shapes that fall through to the fork provider were not traced.
