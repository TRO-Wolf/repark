Label path forward

What six early evaluations found about the remaining format-v2 and format-v3 work, and the order that gets both labels soonest. Companion to the Iceberg label progress page of the same date.

Verdict

The early look retired two risks and found four possible blockers that are not on the gate list. Finding them now costs a ruling or a small unit. Finding them at the re-audit would cost a failed audit, and each of the four audits so far that found a blocker set the label back by days.

The date range on the progress page (v2 near 11-22 to 11-27) can hold, and can improve by a few days, if three things happen: you rule on the questions below this week, a clerk track starts today beside the lane, and a second, cheaper builder takes the two units that share no files with the lane. If the two largest open questions are ruled as blocking, they add about three lane days. These are my estimates.

Retired 2 risks

  • LISTVIEW does not need a DataFusion change. The cause is found and RePark can avoid it on its own side.
  • v3 lineage after schema changes matches Spark in all 14 cells measured. What is missing is tests that assert it.

Smaller than feared 2 units

  • The failed-CTAS cleanup is two call sites and one helper.
  • The 126 loosely checked corpus cases hide only a refusal-text difference, not a wrong answer.

New or larger 4 items

  • Unnamed struct(...) fields are named differently from Spark. Not yet measured on main.
  • Floats nested inside struct, array or map keys treat 0.0 and -0.0 as different.
  • Two proposed v3 carve-outs are silent wrong values, which the label rule does not allow as carve-outs.
  • The corpus checker skips or never reads 2,486 rows, so its repair is larger than planned.

What each evaluation found

1 · AUD-022 and AUD-023

  • All ten verifier findings on #1267 were a missed place or a missed table row. None was a wrong reading of Spark.
  • About two thirds of the PR's diff is struct-comparison code that main now has in another form.
  • 28 cells on 1.5.6 against Spark: 10 match, 15 differ.

2 · LISTVIEW join

  • A rule-by-rule plan trace shows the join intact until eliminate_cross_join, and a cross join after it.
  • Left, right, full, semi and anti joins are correct.
  • The 326-cell table is not on main, and no write was re-measured.

3 · Signed-zero PR B

  • 40 RePark cells: 35 differ from Spark on 1.5.6.
  • The sketch's PR B wraps bare float expressions only, so nested keys stay wrong as sketched.
  • A cost emulation at 10 million rows was inconclusive.

4 · AUD-025, failed CTAS

  • One metadata file is left after any failure once the create has begun, including failures in planning.
  • The audit's "Spark leaves no table directory" holds only for the audit's own spelling. Spark usually leaves orphan data files and no metadata.

5 · Checker, matrix, re-audit readiness

  • 126 of 1,418 confirmed by count. The checker also skips 492 rows and never reads 1,994.
  • The matrix lacks three doors and two seats against plan step 3.1 (the agent's reading).
  • A draft gap list and a re-audit checklist are in the report.

6 · v3 inventory

  • A first inventory by feature and by read, write, evolution and operations, with 33 unmeasured cells.
  • Most exposed: lineage after expire, orphan removal and manifest rewrite; anything on nanosecond tables.
  • Unexplained: Spark reported no delete files where RePark wrote two deletion vectors, with identical rows.
