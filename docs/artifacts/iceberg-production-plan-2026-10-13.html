Iceberg Production Plan

Seven phases, twenty-three units, in the order their dependencies allow. Each unit names what it earns against the twelve attributes in docs/production-grade.md (PR #1044), its grade and tier, its pins, its verifier scope and its exit. Nothing here opens a lane until the owner adopts the phase; the owner's numeric gates are not relaxed anywhere in this page.

Three rules carried through every phase.

1. Floor before fix. Where a silent wrong value is reachable today, the first unit is a named refusal; the real fix follows on its own card and may be slower. A refusal with a hint is production grade inside the envelope; a wrong value never is.

2. Measure before design. Every unit starts with a step 0 that records main's answers for its cells on the live oracle where Spark can answer, and as a committed fixture where it cannot. A unit without a step-0 record does not get a verifier.

3. One seam, one owner. A finding that a verifier reaches through a new spelling of the same plan shape is a seam problem, not a fold problem. Three verifier rounds against the same finding class send the unit to an architecture sketch, never to a fourth fold.

Phase 6 Nanosecond columns, format v3

This is a separate track because its blocker is a type-system seam, not a list of spellings. Seven verifier rounds across two designs (#1027 refusal, three rounds, parked 2026-10-12; #1042 widening, four rounds, parked 2026-10-13) each found a new plan shape through which the narrowing reaches a store: a UNION branch, the cache, a correlated subquery, an alias-less INSERT … SELECT item, a written cast in a WHERE. The cause is one sentence in the registry: the planner's untyped NULL is cast to Timestamp(ns), the session rule reads that cast as SQL TIMESTAMP at microseconds, and the nanosecond argument is narrowed to match. Any fix that walks the plan to find "analyzer-inserted" casts is chasing an open set.

Phase 7 Declare, row by row

Labels move only in STATUS.md, only with the citing tests, only after the unit that earns them merges. The order the labels can move:

  1. Reads on v2 and v3: PRODUCTION once 5.1 states the measured ceiling (no code needed).
  2. Catalogs on Glue and S3 Tables: PRODUCTION after 4.1 and 3.2.
  3. Append, CTAS, INSERT OVERWRITE on top-level common types: PRODUCTION after 2.1, 2.2, 3.1, 3.3 and phase 1.
  4. MERGE, UPDATE, DELETE: PRODUCTION after the same plus 5.2.
  5. Struct-column writes: H-N after 2.4, PRODUCTION after 2.5 and one release of exposure.
  6. Maintenance CALLs: H-N stays until MANIFEST-2/3 close or are declared; PRODUCTION needs a dated ruling on them.
  7. dbt gold: PRODUCTION after 1.1 and 4.1.
  8. Nanosecond columns: H-N after 6.1 to 6.5; PRODUCTION only with a second engine (6.6).
  9. Format v2 as a whole: PRODUCTION when rows 1 to 4 and 7 carry the label; format v3 core: the same rows measured on v3 tables, which the acceptance legs already do.
