Findings worth your eye

  • The example backfill is a divergence detector. Ten silent wrong answers surfaced while measuring examples against the oracle and are now registry rows with pins that flip when fixed: FN-ISNAN-1 (isnan(NULL) is NULL, Spark false), FN-SHA2-1 (facade sha2 returns bytes under a StringType), FN-TRYTONUMBER-1 (non-foldable format silently wrong), FN-LAST-1 (window last with ignorenulls), FN-APPROXPCT-1 (interpolated double vs Spark's discrete bigint), FN-ARRAYPOS-1, FN-ARRAYSORT-1, FN-ARRAYSOVERLAP-1, FN-FLATTEN-1, FN-ADDMONTHS-1 (month-end arithmetic lands on the target month's last day where Spark keeps the day; a repark test had pinned the wrong values as Spark's). Plus one queue entry: createDataFrame stores a Python NaN as NULL. Recommendation: one unit, FN-FIX-1, after the tag.
  • Two example defects a green gate could not see. first/last and listagg examples asserted order-dependent values that flip under repartition on Spark; the coverage gate runs under single-node repark and stayed green. Both rewritten to order-insensitive assertions; the lesson is in the critic brief.
  • V3-COV found what the create rows hid. Comparing the created tables' metadata (not just "no error") exposed V3-COV-7 (Spark stamps write.parquet.compression-codec at CREATE) and V3-COV-8 (CTAS derives id: long optional where Spark derives int required) — both BACKLOG, both outside the gate cell, both worth a look before v1.1.
  • Spark's file order is deterministic after F-20. The partitioned INSERT row-id flap V3-COV measured (7 of 12 runs Spark's mapping) is the fork's FanoutWriter draining in HashMap order; F-20 makes it ascending and RP-8 re-measures twelve runs at the new pin.
  • One regression found by the perf reviewer, on purpose. F-22 made the fork's DV close walk every data manifest on every MoR statement (to fill a sequence-number map RePark never reads): +39 % statement wall at 192 data manifests on the pure-DV path, about 3.3 ms per manifest, hidden by a measurement cell whose fixture cancelled the two walks. RP-8 merges with it recorded (PERF-DVCLOSE-WALK-1, ledger errata E-4); fork F-23 (conditional walk + early exit) is running on Grok and RP-9 repins after it.
  • Provider notes. z.ai reset GLM sessions all night (a watchdog auto-relaunched from the tree state); the free Spark contributor finished first cuts in 5–15 minutes but stalled on relaunches after 04:00 and omitted trailers twice; Grok 4.6 carried every remediation round cleanly (F-21 r3–r5, F-22 r1–r4, ≈$18 total).
