2. Q11, NaN with the sign bit set: which seat

The audit showed the premise was wrong. Spark also keeps sign-bit NaNs in memory, from sqrt(-1.0), from the arithmetic operators and from aggregates. The real gap is comparison: Spark treats every NaN as one value, the largest, while RePark compares by bits, so a sign-bit NaN sorts first, loses max, and fails = NaN. Spark's Iceberg write stores the canonical NaN.

(A) canonicalise every producer, which puts work on every float operation; (B) adopt Spark's NaN comparison in min/max, greatest/least, sort and equality, and canonicalise on write; (C) canonicalise only at RePark's Iceberg/Parquet write.

C before the label, as NAN-WRITE-CANONICAL-1. It changes NaN only, and never -0.0, so it does not reuse part B's kernel. You accept a label exclusion: max, min, greatest, least and comparisons over a NaN computed in the same query still differ from Spark. Its text is measured on the head that carries part B and C.
