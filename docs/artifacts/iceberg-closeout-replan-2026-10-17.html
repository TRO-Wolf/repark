7. Halt rules and risks

Halts, carried from the standing guidance

  • A FAIL verdict parks the unit and the owner hears first; no third round unless the owner names it (55, 73).
  • A second seam in any sketch halts the same day and re-plans the label date (8).
  • A red acceptance run stops every lane until it is explained (63).
  • The U drill showing a double append stops the live leg and v2 waits (84).
  • Any statement main answers that a head refuses, outside the named carve-outs, halts (70).
  • Every write-path merge carries its P2 report, cell count, verdicts first, acceptance run id, before the next lane opens (standing guidance 4).

Risks, with the fallback

  • PP-01 cannot be bounded without a redesign. The audit says the input vector must become budgeted or spillable. Fallback: the bound is declared and exceeded means refused; the definition allows "refuses cleanly where it cannot spill". Spilling is a later unit.
  • The fork's next_row_id fix is large. Row lineage is v3 core; it cannot be carved out. Fallback: the v3 label slides into the buffer, v2 does not.
  • The first integrity nightly is red for harness reasons (gate signing, S3 Tables maintenance mid-drill). One Muse fold with a scoped re-verifier; retry once on maintenance (87).
  • The parity drift is a real Spark behaviour change. Re-record with a dated note; the affected registry rows are re-measured in U-13.
  • Opus usage crosses the line mid-week. Lane A finishes its commit and hands back; verifiers continue; Muse continues.
  • Box disk. Every finished lane's clone is removed at merge; U-9's cross-release venv and the fork clones are the new consumers.
