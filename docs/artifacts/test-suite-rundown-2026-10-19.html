2. What changes day to day

  • A new test goes in the directory of the subsystem it pins. A new subsystem is a new directory with its own map.md. The rule is written in docs/testing.md; the nine shared helpers and conftest.py stay at the root, and pytest's import mode puts both the root and the file's own directory on the path.
  • Inner loop: make py-test-facade-fast runs everything except the 19 slow files in about 90 seconds after the build. CI still runs everything.
  • Full facade stage: make py-test-facade is about six minutes after the build, against 24 this morning and 69 two days ago. FACADE_WORKERS overrides the worker count.
  • Strictness: an unregistered marker or an unknown ini key is now an error; an xfail that passes is now a failure; a test that runs past 1200 s is killed and named.
  • New files may use the shared fixtures spark (per-test session named after the node, stopped on teardown; 93 of the 283 local fixtures had this exact body) and spark_with_warehouse (a mem catalog rooted at tmp_path with namespace mem.ns; the second-commonest body at 17 files). Existing files were not rewritten.
  • Open branches with test files (#1048, #1047, #1038, #1037, #1014, #1011, #1000, #888, #884, #881, #643, #411) merge main normally: git resolves rename-plus-modify, and a new file they add at the flat root is still collected. Move it into its directory when the branch is picked up.

5. Findings for the owner

  1. The 20,000-term OR build is quadratic on the Python door. Building reduce(lambda x, y: x | y, …) over Column objects costs 2.3 s at 2,500 terms, 11.0 s at 5,000, 58.2 s at 10,000 and 286 s at 20,000, while the filter().count() refusal itself stays under 0.1 s. That is product code in the facade's Column expression build, not the test, and it is now the whole floor of the suite. A perf unit could measure where the growth is (string rendering of the fragment at each level, or the binding) and fix it under the usual like-for-like gate.
  2. A timing pin flaked under load. perf/test_perf_unpivot_1.py::test_stack_is_linear_in_columns failed once in a baseline run with an exponent of 1.415 against its 1.1 bound while other work had the box at load 10 to 17; it passed in every run on a quiet box. It is the fourth timing-shaped flake candidate after the spill, OCC and fence cards.
  3. One cold wheel build on CI. The config PR's wheel took 29.9 min compiling 487 crates: rust-cache's environment hash rotated between the morning and the afternoon, so no key matched. Main re-saved under the new hash at 19:11 UTC and the next PR hit again at 10.7 min. Nothing in the PRs caused it; a bumped runner image is the usual reason.
  4. One frozen digest re-recorded. python/repark-parity/tests/test_sqp_1_record.py is byte-frozen by a digest in the PR-245 revalidation pin; its only change is the path of a test file it reads. The digest was re-recorded, the same remedy the v3 lineage tripwire uses.
  5. Squash merges lose shared history. Each of the three branches had merged the previous one, and after each squash the next branch still needed a hand merge of main. Stacked PRs in this repo cost one hand merge per step; a single PR per step would not.
  6. Stale dated entries stay. The scheduler entry in the tests map still describes the module-wide groups that #1115 removes; the sql directory map records the change. The three code comments that say a file "lives at python/repark/tests/" were left, since rewriting them would add comment lines.
