2b. U-4 — ICE-TSNS-UPDATE-RANGE-CLASS-1 (row R-012): the unfiltered UPDATE reports the truthful refusal class

Under strict mode, UPDATE t SET v = TIMESTAMP '3000-01-01 ...' with no WHERE into a nanosecond column refuses as "malformed" (CAST_INVALID_INPUT), where INSERT and UPDATE ... WHERE refuse the same value as "out of range" (CAST_OVERFLOW). 16 measured cells: two far literals in three zones and each zone's edge instant, in both row-level modes. With strict mode off all three store NULL, which stays. No value is ever mis-stored; the unit changes the class and text of one refusal so the three paths agree. The cause is known from the row: the unfiltered UPDATE runs INSERT's conform path, whose literal check fires before the range check.

Order: grade C, written by the orchestrator from the row and the conform-stage map (one seam: the range check runs before the literal check on that path, or the unfiltered UPDATE takes the filtered path's check). Red-first: the 16 cells as facade pins plus one Rust pin beside the existing R-012 pin in crates/repark-sql/src/v3/create.rs; the INSERT and filtered-UPDATE cells stay as controls (their class must not change). Gates as every product PR: comment grep, clippy, panic ban, file sizes, ledger grammar, map lockstep by the clerk, cost on the write set within 1.05. Builder and verifier tiers are decision D2. Target: order Mon 10-27, build Tue 10-28, verify Wed 10-29, merged by Fri 10-30.
