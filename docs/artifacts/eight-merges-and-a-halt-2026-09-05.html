The halt: a shared cache that remembered the wrong caller

The fork's new shared manifest cache keys a parsed manifest by its path. But the parsed object is not a pure function of the file: after parsing, the fork stamps each entry with the caller's manifest-list context, including the row-id range a v3 table assigns. A v2 table carries no range; after an upgrade to v3 the same manifest path carries one. First parse wins, so a v2-context read poisoned every later v3 lineage read of that path, and four upgrade tests answered NULL row ids with the cache on.

The Muse worker stopped and filed it rather than pin around it. The ruling was to ship the RePark side with the cache off by default plus pins that turn red when the fork is fixed, and to fix the fork in parallel. The fix is up as fork #270 with CI green; the default-ON flip is a follow-up after the next pin bump.
