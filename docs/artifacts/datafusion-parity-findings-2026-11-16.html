Planning board · 2026-11-16 · main before #1341 · one sweep and one audit

DataFusion parity findings

What a type-pair sweep and a rewrite audit measured about where RePark answers unlike Spark 4.1.2 on scalar SQL, and what the planning agent recommends doing about it.

Verdict

DataFusion's engine is sound. Its semantic layer differs from Spark in three ways, and the differences are now counted. On scalar SQL through the Spark door, 2,000 of 8,442 cells differ with ANSI off and 859 with ANSI on. They sort into 17 families, plus six simplifier rewrites that change an answer.

The recommendation is to stop fixing these one family at a time and to narrow what the label promises: scope the label to ANSI on, build one Spark common-type rule and one Spark cast unit, and size a patched simplifier for the upstream bugs.

Recommendations, in priority order

  1. Scope the label to ANSI on. It is Spark 4's default, and it cuts the differing cells from 2,000 to 859 and the refusals from 1,470 to 355. ANSI-off behaviour becomes a named exclusion and a later unit.
  2. Rule severity on the silent, everyday findings first: extract ignoring the session zone, the number-to-timestamp cast, small-integer wrap under ANSI, and an integer beside a FLOAT under ANSI. The AND guard is loud but very common and belongs on the same list.
  3. Build DECIMAL-COMMON-TYPE-1 as the first slice of one Spark common-type rule: one shared function and one walk, so the other type families become additions to that seat.
  4. Plan one Spark cast unit for text parsing and the number-to-timestamp cast. Text-to-number parsing under ANSI on should come before the label, because ingestion casts are what the label is for.
  5. Size a patched DataFusion simplifier for the five upstream bugs before writing five guards, and report them upstream. The wrap stays the fix for the lossy cast, because it also keeps pruning.
  6. Keep the sweep as a standing check. Rerun it on current main now and after each coercion unit.

Not recommended: switching engines or forking DataFusion wholesale. Nothing here touches execution or speed.

Decisions waiting on you

How far to trust this

  • Narrow surface. Scalar SQL on the Spark door over temp views. No Iceberg table, no DataFrame door, no store, no NaN or -0.0 values.
  • Stale cells. The package predates #1341, so its decimal-beside-double VALUES, union and IN cells need a rerun.
  • Card matching is by name only. Some findings may already be carded.
  • The agents were Haiku 5.5 and Sonnet 5.5. The planning agent re-measured the sweep's sample and every finding in the third table. Eight further audit findings were not re-measured and are left off this page.
  • One audit claim was dropped. date_trunc does not ignore the session zone; the agent had compared rendered timestamps.
